# Как получить событие `performance update` в технологическом журнале 1С


## 1. Подготовка файла конфигурации

Создайте (или отредактируйте существующий) файл **`logcfg.xml`** и поместите его в каталог:  
`C:\Program Files\1cv8\<версия>\bin\conf`


## 2. Настройка содержимого файла


Вставьте в `logcfg.xml` следующую структуру (пример для сбора событий `performance update`):


```xml
<?xml version="1.0" encoding="UTF-8"?>
<config xmlns="http://v8.1c.ru/v8/tech-log">
    <log history="72" location="C:\LOG">
        <event>
            <eq property="name" value="PERFORMANCE_UPDATE"/>
        </event>
    </log>
</config>
```

### Ключевые параметры

- **`history="72"`** — время хранения логов в часах (в примере — 3 суток);
- **`location="C:\LOG"`** — путь к каталогу для сохранения логов;
- **`<eq property="name" value="PERFORMANCE_UPDATE"/>`** — указание на сбор событий `performance update`.

## 3. Создание каталогов


Убедитесь, что:
- папка `C:\LOG` существует;
- у сервера 1С есть права на запись в эту папку.


## 4. Активация журнала

1. Перезапустите сервер 1С или клиентское приложение.
2. Через 1–2 минуты в `C:\LOG` появятся подпапки с логами.

## 5. Как выглядит событие в логах


В файлах логов событие представлено строкой формата:

```
24:08.491033-0,CLSTR,Event=Performance update,Data='process=tcp://SRV1:1586,pid=22804,sql=0,cpu=15,queue_length=0,queue_length/cpu_num=0,memory_performance=28,disk_performance=12,response_time=55,average_response_time=58.24'
```

### Расшифровка полей


- `process` — адрес процесса;
- `pid` — идентификатор процесса;
- `sql` — время запросов к БД (мс);
- `cpu` — загрузка процессора (%);
- `queue_length` — длина очереди к процессору. Не должна быть больше количества доступных ядер процессора;
- `memory_performance` — производительность операций с памятью;
- `disk_performance` — производительность дисковых операций;
- `response_time` — время отклика (мс);
- `average_response_time` — среднее время отклика за период (мс). Должно быть больше 1 000 000.

## 6. Проверка работы

1. Откройте папку `C:\LOG`.
2. Найдите подпапку с именем процесса (например, `rphost_1234`).
3. Откройте самый свежий файл `.log` в этой папке.
4. Поищите строки с `Event=Performance update`.


## 7. Типичные проблемы и их решение


| Проблема | Решение |
|--------|--------|
| Нет событий в логах | Проверьте: <br> - правильность написания `PERFORMANCE_UPDATE`; <br> - размещение `logcfg.xml` в нужной папке; <br> - перезапуск сервера 1С после изменений. |
| Ошибка доступа к папке | Предоставьте права на запись в `C:\LOG` для учётной записи сервера 1С. |
| Быстрый рост объёма логов | - Сократите `history` (например, до `24`); <br> - добавьте фильтры по другим событиям. |


## 8. Анализ данных


Для мониторинга производительности обращайте внимание на:

- **CPU > 80 %** — перегрузка процессора;
- **queue_length > 2** — длинная очередь к процессору;
- **response_time** и **average_response_time** — рост значений указывает на замедление системы;
- **memory_performance** и **disk_performance** — низкие значения сигнализируют о проблемах с памятью/диском.
